A **workspace** is where a team and its assistants work together. People write in
**threads**, mention an assistant or address one directly, and the assistant
answers in the same thread, with the tools, knowledge and rules the workspace
gives it.

Workspaces live in the web app and the mobile app. Everything they do is also
available [from the API and the CLI](/devic/workspaces/api-and-cli), with the
same permissions.

## How an assistant takes part

An assistant answers when someone addresses it, either by mentioning it or by
replying to one of its messages. The workspace can also be set to suggest an
assistant, or to bring one in automatically.

While it works, the run is visible in the thread: thinking, writing, the tools
it calls. Sometimes it waits for a person:

- **A question.** The assistant asks with options or free text, and the run
  continues with the answer.
- **An approval.** Some tools, such as the terminal, need someone to approve
  them before they run.

Through the API these are runs in `waiting_input` and `waiting_approval`, and
you can answer or approve them from there too.

## Roles

| Role | Can |
|---|---|
| Viewer | Read threads, files, rules and memory |
| Member | All of the above, plus write, answer and approve runs, edit memory and thread rules |
| Manager | All of the above, plus manage automations and skills. An account admin who is a manager also edits settings, members, assistants, knowledge and workspace rules |
| Owner | Everything, including ownership |

A personal workspace belongs to one person and nobody else can see it.

## Messages written outside the apps

Messages written through the [public API, the CLI or the SDK](/devic/workspaces/api-and-cli)
carry a small **via API**, **via CLI** or **via SDK** tag next to the author. The
tag's tooltip says how the message was sent: by the person through an
authorized app, with an API key on the person's behalf, or by an API key with
no person behind it, shown as **API**.
